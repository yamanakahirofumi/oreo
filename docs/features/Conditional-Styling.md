# 条件付きスタイル表示 (Conditional Styling)

OREO (**Overpowered Rich Editor for Overlords**) では、テキストの内容に応じてフォントの色や太さ、装飾などを動的に変更して表示する機能を備えます。

## 1. 概要

ユーザーが別途定義した「スタイルルール」に基づき、エディタ上のテキストを装飾します。これにより、シンタックスハイライト（構文強調）や、特定のキーワードの強調表示を実現します。

## 2. スタイルルールの定義

スタイルルールは、以下の要素で構成されます。

- **条件 (Condition)**: スタイルを適用する対象を特定するための条件。
    - 正規表現 (Regex): 文字列パターンによるマッチング。
    - キーワードリスト: 特定の単語セット。
    - 範囲指定: 特定の行や文字範囲。
- **スタイル属性 (Attributes)**: 条件に合致したテキストに適用する外観情報。
    - フォントカラー (Color)
    - 背景色 (Background Color)
    - 太字 (Bold)
    - イタリック (Italic)
    - アンダーライン (Underline)
    - 取り消し線 (Strikethrough)

## 3. 実装方針

### 3.1 描画エンジン
JavaFX 標準の `TextArea` は複数のスタイルを混在させることができないため、以下のいずれかのアプローチを採用します。

1. **RichTextFX の活用**: JavaFX 用の定評あるコードエディタライブラリ。高機能だが、メモリ使用量抑制のポリシーとの整合性を慎重に検証する必要がある。
2. **TextFlow + ScrollPane によるカスタム実装**: 編集中の行や可視範囲のみを `Text` オブジェクトとしてレンダリングする。メモリ効率は高いが、カーソル管理や編集ロジックの実装負荷が高い。

### 3.2 パフォーマンス考慮
- **遅延レンダリング**: 画面に表示されている範囲（ビューポート）とその周辺のみスタイル計算・適用を行う。
- **非同期計算**: 大規模なファイルや複雑な正規表現の場合、スタイル計算をバックグラウンドスレッドで行い、UI の応答性を損なわないようにする。
- **インクリメンタル更新**: テキストの変更があった箇所のみ再計算を行う。

## 4. 拡張性
- **言語プロファイル**: Markdown, Java, SQL など、言語ごとのスタイル定義を外部ファイル（JSON または SQLite）からロードできる仕組みを提供します。
- **動的切り替え**: 編集中のドキュメントの種類に応じて、適用するスタイルセットを即座に切り替えられるようにします。
