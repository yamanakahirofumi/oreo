# コアコンセプト

OREO (**Overpowered Rich Editor for Overlords**) は、シンプルさと強力な機能を両立させたテキストエディタです。
本ドキュメントでは、OREOの設計における中心的な考え方を定義します。

## 1. OS非依存 (OS-Independent)

OREOは、特定のオペレーティングシステムに依存せず、どこでも同じように動作することを目指しています。

- **クロスプラットフォーム対応**: Windows, macOS, Linuxの主要なOSにおいて、同一の機能とユーザー体験を提供します。
- **JavaFXの採用**: JavaFXを利用することで、各OSのネイティブな描画エンジンを活用しつつ、一貫したUI/UXを実現します。
- **ランタイム同梱**: 各プラットフォーム向けのカスタムJREを同梱して配布することで、ユーザー環境にJavaがインストールされていなくても動作するようにします。

## 2. シンプル・ミニマル (Simple & Minimalist)

OREOは、ユーザーが執筆やプログラミングに集中できるよう、デフォルトのビジュアルを極力シンプルに保ちます。

- **装飾の排除**: 不要なツールバーやボタンを排除し、コンテンツ（テキスト）が主役となるインターフェースを提供します。
- **直感的な操作**: 機能は豊富でありながら、初期状態では複雑さを感じさせない、洗練されたデザインを目指します。

## 3. キーボード中心の操作 (Keyboard-Centric)

OREOは、効率的な編集体験を提供するため、マウスに頼らないキーボード主体の操作を重視します。

- **マウスレス・ナビゲーション**: ファイルの切り替え、設定の変更、ウィンドウの分割など、あらゆる操作をキーボードだけで完結させます。
- **Emacsライクなショートカット**: `Ctrl-x` や `Meta-x` といった、複雑なコマンドを迅速に実行できるマルチストローク・キーバインドをサポートします。
- **コマンド実行システム (Mini-buffer)**: メニューを辿ることなく、コマンド名を入力することで機能を呼び出せる仕組みを提供します。現在の状態やフィードバックもここに表示されます。
- **モーダルでない柔軟性**: 基本的には挿入モードとコマンドモードを分けない（Emacsスタイル）ことで、シームレスな入力を実現します。

## 4. 拡張性 (Extensibility)

OREOは、コア機能をシンプルに保ちつつ、ユーザーが必要な機能を後から追加できる柔軟な設計を目指します。

- **プラグイン・アーキテクチャ**: エディタの挙動や外観、新しい言語のサポートなどをプラグインとして分離できる構造を持たせます。
- **Java開発補助の実現**: 将来的に、静的解析やコード補完などのJava開発を支援する機能を、コアを汚さずにプラグインとして追加できる余地を残します。ただし、これらは「最低限のサポート」を基本とし、IDEのような重厚な機能ではなく、シンプルさを損なわない軽量な実装を目指します。
- **LSP (Language Server Protocol) の活用**: 標準的なプロトコルをサポートすることで、多様な言語への「最低限の対応」を効率的に行えるように設計します。

## 5. リソース効率 (Resource Efficiency)

OREOは、高性能なテキストエディタでありながら、システムリソース（特にメモリ）の消費を最小限に抑えることを実装ポリシーとして掲げています。

- **メモリ使用量の抑制**: 大規模なファイルを開いた際や、長時間の利用においても、メモリ消費が肥大化しないようなデータ構造とアルゴリズムを選択します。
- **軽量な動作**: 起動速度の高速化やUIの応答性を維持するため、不要なオブジェクト生成を避け、効率的なリソース管理を行います。
- **「Overpowered」の解釈**: OREOにおける「Overpowered」とは、単に機能が豊富であることだけでなく、極めて高い効率性（少ないリソースで最大のパフォーマンスを発揮すること）も意味しています。
