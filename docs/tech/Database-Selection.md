# データ永続化方針

本アプリケーションでは、ユーザーの設定情報、最近開いたファイルの履歴、および将来的な拡張機能（スニペット、プラグイン設定など）を効率的に管理するため、適切なデータ永続化手段を採用します。

## 1. 永続化対象データ

| データ種類 | 内容 | 推奨される保存形式 |
| :--- | :--- | :--- |
| **ユーザー設定** | フォント、テーマ、エディタの動作設定など。 | SQLite |
| **アプリケーション履歴** | 最近開いたファイル、検索履歴など。 | SQLite |
| **拡張データ** | ユーザー定義スニペット、プラグイン固有のデータ。 | SQLite |

## 2. データベース候補 (履歴・拡張データ・設定用)

比較的小規模なメタデータの管理に限定されるため、以下のファイルベース RDB を検討します。

| 候補 | 特徴 | メリット | デメリット |
| :--- | :--- | :--- | :--- |
| **SQLite** | 軽量で広く普及している RDB。 | 汎用性が高く、外部ツールでの閲覧が容易。 | 設定が不要。 |
| **H2 Database** | Java 製の軽量 RDB。 | Java との親和性が非常に高い。高速。 | Java 実行環境に依存。 |

## 3. 選定結果：SQLite

本プロジェクトでは、履歴管理や設定データの保存に **SQLite** を採用します。

### 選定理由
1. **ポータビリティ**: 1ファイルで完結するため、バックアップや移行が容易です。
2. **フットプリント**: ライブラリが軽量であり、エディタの起動速度やメモリ消費への影響が最小限です。
3. **将来性**: 単純な設定ファイル（JSON等）では管理が困難な、大量の履歴データやスニペットの検索・管理にも柔軟に対応可能です。
4. **一元管理**: 設定情報と履歴情報を同じデータベース形式で扱うことで、アクセスロジックを共通化できます。

## 4. アクセス方式

Java から SQLite へアクセスするために、以下のスタックを採用します。

- **Driver**: [sqlite-jdbc](https://github.com/xerial/sqlite-jdbc)
- **Data Access**: シンプルな **Repository パターン** を介した JDBC アクセス。
    - *方針*: 高度な ORM はオーバーヘッドとなるため、基本的には直接的な SQL 発行、または薄いラッパーライブラリを使用します。

## 5. データ保存場所

アプリケーションのデータディレクトリ（OS ごとの標準的な場所）に保存します。
- **Windows**: `%APPDATA%/OREO/`
- **macOS**: `~/Library/Application Support/OREO/`
- **Linux**: `~/.config/oreo/`
