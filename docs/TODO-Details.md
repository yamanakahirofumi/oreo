# 検討事項・TODOリスト

OREO (**Overpowered Rich Editor for Overlords**) の開発における検討事項およびTODOリストです。

## 1. 技術面
- [x] **ドキュメントの刷新**
    - **完了日**: 2026-05-27
    - **概要**: 既存の技術ドキュメントをテキストエディタ「OREO」向けに全面的に書き換え完了。
- [x] **SQLite による設定情報の永続化実装**
    - **完了日**: 2026-05-27
    - **概要**: 設定情報を SQLite ファイルに保存し、アプリ再起動時に復元できるようにする仕組みを実装。
    - **解決策**: `PersistenceService` および `SQLitePersistenceService` を実装し、OS ごとの標準的なパスにデータベースファイルを生成するようにした。
- [ ] **テキストデータ構造の選定**
    - **概要**: 大規模ファイルの編集時におけるパフォーマンスとメモリ効率を両立するデータ構造を選定する。
    - **検討内容**:
        - Gap Buffer: 実装が比較的単純で、局所的な編集に強い。
        - Piece Table: メモリ効率が非常に良く、Undo/Redo の実装と相性が良い。大規模ファイルに強い。

## 2. 機能・仕様面
- [x] **タブ機能（マルチドキュメント対応）の基本実装**
    - **完了日**: 2026-05-28
    - **概要**: 複数のファイルをタブ形式で開き、編集できるようにする。
    - **解決策**: `TabPane` を採用し、各タブで独立したエディタ（TextArea）を保持する構造を実装。また、未保存の変更がある場合にタブ名に `*` を表示するインジケータ機能を実装。
- [x] **ファイルの保存機能 (Ctrl+S)**
    - **完了日**: 2026-05-28
    - **概要**: ショートカットキーによるファイル保存機能を実装。
    - **解決策**: `FileIOService` を作成し、`EditorController` に保存ロジックを実装。`Main.java` で `Ctrl+S` (Mac では `Cmd+S`) を紐付けた。新規ファイルの場合は `FileChooser` を表示する。
- [ ] **エディタ基本機能の定義**
    - **概要**: テキストエディタとしての最小限の機能を定義する。
    - **検討内容**:
        - 対応ファイル形式（プレーンテキスト、Markdown等）。
        - 文字コードの扱い（UTF-8固定か、自動判別か）。
        - 大規模ファイルのハンドリング方針。
- [ ] **コマンドショートカット機能の設計**
    - **概要**: Emacsライクなマルチストローク・キーバインドおよびコマンド実行の仕組みを設計する。
    - **検討内容**:
        - キーバインドのカスタマイズ性（ユーザー定義のキーバインド設定）。
        - `Ctrl-x` 等のプレフィックスキーの処理アルゴリズム。
        - コマンドパレット（M-x）のUIデザイン（シンプルさを保ちつつ、補完機能をどう提供するか）。
        - **キーイベント処理の抽象化**: OS固有のキーコードをアプリケーション独自の「コマンド」に変換するレイヤーの設計。
        - **フォーカス管理**: ミニバッファとエディタ間でのスムーズなフォーカス遷移の仕組み。

- [x] **基盤コンポーネントの選定**
    - **完了日**: 2026-05-28
    - **概要**: `TextArea` から `RichTextFX` への移行方針を決定。
    - **解決策**: [エディタコンポーネントの比較検討](tech/Editor-Component-Comparison.md) を作成し、メモリ効率と機能性のバランスが最も良い `RichTextFX` を次期基盤として選定した。
        - **スタイルルールのデータ構造**: SQLite または外部ファイルでのスタイル定義の保持。
        - **リアルタイム反映の最適化**: 入力ごとのスタイル再計算アルゴリズム。
- [x] **行番号表示の基本実装と設定連携**
    - **完了日**: 2026-05-28
    - **概要**: エディタ左端に行番号を表示し、SQLite を介した設定で表示/非表示を切り替え可能にした。
    - **解決策**: `EditorConfig` モデルを導入し、`EditorController` でエディタ本体と行番号エリアを `HBox` で管理する構造を実装。
- [ ] **カーソル・行の視認性向上機能の実装**
    - **概要**: 編集中の行やカーソル位置を分かりやすくする視覚効果を実装する。
    - **検討内容**:
        - **カレント行強調の実装**: 背景色変更（`RichTextFX` 依存）またはガターでのマーカー表示。
        - **設定項目**: ユーザーが好みの強調方法を選択できる仕組み。
- [ ] **Markdownプレビュー機能の設計**
    - **概要**: Markdown等のマークアップ言語の描画確認機能を設計する。
    - **検討内容**:
        - **表示方式**: 左右分割（Split View）、またはタブ切り替え、あるいは別ウィンドウ。
        - **レンダリング方式の選定**: [実現方式の比較検討](tech/Markdown-Preview-Implementation.md) に基づき、Native Node Rendering を第一候補として技術検証を行う。
        - **WebView 採用時のリソース管理**: WebView を採用する場合のインスタンスのライフサイクル管理（オンデマンド起動・破棄）。
        - **使用ライブラリ**: `flexmark-java` 等のパーサー選定。
        - **同期タイミング**: 入力ごとのリアルタイム更新か、保存時またはコマンド実行時のみ更新するか。
- [ ] **プラグインシステムの基本設計**
    - **概要**: 外部機能を追加するためのプラグイン機構を設計する。
    - **検討内容**:
        - **プラグイン形式**: Jar ファイルの動的ロード、またはスクリプト言語（Lua, JavaScript等）のサポート。
        - **API の公開範囲**: エディタのコアバッファ、キーバインド、UIコンポーネントへのアクセス制限と権限管理。
        - **配布・管理方法**: プラグインのインストールディレクトリ、設定ファイルの管理方法。
- [ ] **Java開発補助・LSP連携の検討（最低限のサポート）**
    - **概要**: Java開発を支援するための機能を、将来的にプラグインとして提供するための準備を行う。IDEの代替ではなく、軽量なエディタとしての利便性を重視する。
    - **検討内容**:
        - **LSP クライアントライブラリの選定**: lsp4j 等の利用検討（軽量な統合方法の模索）。
        - **シンタックスハイライトの拡張性**: 言語ごとの解析エンジンを動的に切り替える仕組み。
        - **ビジュアルとの整合性**: エラー表示や補完ウィンドウが「シンプル・ミニマル」な外観を損なわないようなデザイン案。
        - **バックエンドプロセスの管理**: 言語サーバープロセスの起動・停止・通信管理（リソース消費を最小限に抑える構成）。

## 3. UI/UXデザイン面
- [x] **フッター（ステータスバー）の基本実装**
    - **完了日**: 2026-05-28
    - **概要**: 画面下部に情報を表示するためのフッター領域を追加。
    - **解決策**: `EditorWindow.fxml` に `bottom` エリアを追加し、`EditorController` でカーソル位置（行・列）を表示するロジックを実装。また、フッターを N 分割（デフォルト 3 分割）して複数の情報を並行して表示できるマルチセクション構造を導入。
- [ ] **シンプル・ミニマルなビジュアルの定義**
    - **概要**: 「極力シンプル」を実現するための具体的なデザイン案を策定する。
    - **検討内容**:
        - メニューバーの非表示（Altキーやハンバーガーメニュー等での呼び出し）。
        - ステータスバーの情報の最小化。
        - デフォルトテーマ（ダークモード/ライトモード）の選定。
- [x] **OS非依存のUIデザイン方針**
    - **完了日**: 2026-05-28
    - **概要**: 全OSで一貫したUIを提供するためのデザインガイドラインの策定。
    - **解決策**: [コーディング規約](../tech/Coding-Convention.md) および [キーボード操作の詳細仕様](../features/Keyboard-Interactions.md) にて、OS ごとの修飾キー（Shortcut, Control, Meta）の割り当て方針を定義。JavaFX の `SHORTCUT_DOWN` を活用し、macOS では Command、他では Ctrl を自動的に使い分ける実装ルールを策定。
    - **検討内容**:
        - カスタムタイトルバーの採用可否（シンプルさを優先するか、OSの慣習を優先するか）。
